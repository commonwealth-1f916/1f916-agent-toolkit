# 1F916 — bridged sittings

Status: `queue/task-2026-09-21-bridged-sittings-split-from-the-brief` (rev. 2026-10-26, third). Split from `docs/brief.md`, which points here. Read by a sitting with the desktop bridge; no scheduled run needs it.

Rules for a sitting with the desktop bridge (rev. 2026-09-13). First, before any other read: no `project_search` in the project, ever; the docs are read at the pinned commit in the Mac clone, and the project's own docs by name with `project_read` (brief rule 1; why: notes/2026-10-07-lesson-sitting-ran-project-search) (rev. 2026-10-12). (a) Ask for the `~/Projects` and `/private/tmp` grants at the start; `/tmp` is a symlink and a grant request naming it is refused, taking the rest of the request with it (why: `notes/2026-09-20-why-private-tmp-grant`) (rev. 2026-09-20). Files carried to the Mac and Mac-side logs and worktrees go under `/tmp/1f916-<YYYY-MM-DD>/`, never loose in `~/Projects`, and nothing carrying credential bytes goes there (why: `notes/2026-09-17-mac-temp-files-go-to-a-dated-tmp-folder`) (rev. 2026-09-17). A sitting that writes with git in a mounted clone first asks once, with `device_request_delete_permission`, for delete permission on the connected roots it will touch, because the mount refuses unlink until then and git cannot clear its own lock files; with the grant, git runs from `device_bash` (measured 2026-10-05, bridged Cowork sitting, manual mode; the grant lasts one session). Without it, `device_bash` inside a mounted clone reads files and runs no git. Signing stays in a Ghostty window (h) (why: `notes/2026-10-05-git-in-a-mounted-clone-works-after-the-delete-grant`; `notes/2026-10-01-lesson-git-from-the-cowork-vm-leaves-locks-in-the-mac-clone`) (rev. 2026-10-05). Before touching the deployment clone, assert `git rev-parse --abbrev-ref HEAD` is `main` and the tree is clean, and report a deviation rather than fixing it silently: `~/bin/1f916-gate` and `~/bin/1f916-scan` are symlinks into that clone, so whatever branch it sits on is what runs (why: `notes/2026-09-20-the-deployment-clone-was-parked-on-a-topic-branch`) (rev. 2026-09-21). (b) A container-built commit for a public branch is created or amended with `commit.gpgsign=false` before it leaves the container; the Mac asserts `%G?` beside the tree (why: `notes/2026-09-13-container-auto-signs-commits`). (c) Build logs live outside the clone; the file list a reviewer will see is read BEFORE any push AS A LIST OF NAMES — `git diff --name-only <base>..HEAD`, or `--stat` read in full — never a count and never a `tail -1` summary, and the sitting's runs row records the names it read rather than a number (why: `notes/2026-09-09-the-pr-carried-19366-lines-of-our-own-scratch`; `notes/2026-09-14-lesson-file-count-is-not-a-file-list`, where a correct-looking count absorbed a stray `__pycache__` file the day after this rule was written) (rev. 2026-09-14). (d) A hygiene pass greps, reads the result, then deletes — never in one command (why: `notes/2026-09-11-the-cleanup-deleted-the-evidence-it-flagged`). (e) Every file carried over the bridge is hashed on both sides before use, and an osascript exit status is never read as the child process's outcome (why: `notes/2026-09-08-device-commit-reported-a-write-that-did-not-land`, `notes/2026-09-08-osascript-error-after-a-successful-write`). A prompt handed to the operator by clipboard is copied and checked with `LANG=en_US.UTF-8 LC_ALL=en_US.UTF-8` set for both pbcopy and pbpaste, and after every paste the stored prompt is byte-diffed from `list_triggers` before its `prompts` row is written (why: notes/2026-10-20-lesson-pbcopy-without-a-utf8-locale-garbles-a-pasted-prompt) (rev. 2026-10-26). Delivery mechanics: `docs/delivery-runbook.md`.

(f) Four rules the sittings have already paid for. An interrupted delegation leaves a real artifact, so the next step is a read of the target rather than a re-run (why: `notes/2026-09-14-lesson-an-interrupted-delegation-leaves-a-real-artifact`). A renumber can rename a reference it does not own (why: `notes/2026-09-17-lesson-a-renumber-can-rename-a-reference-it-does-not-own`). A stop hook can ask for an unsigned duplicate push, and is declined (why: `notes/lesson-2026-09-20-the-hook-that-asks-you-to-push-an-unsigned-duplicate`). The journal window does not reach thirty days, so report the window that exists beside the window asked for (why: `notes/2026-09-14-the-journal-does-not-reach-thirty-days`) (rev. 2026-09-21).

(g) A bridged sitting runs `~/bin/1f916-gate key-check` under `op run` near its start, which signs, compares and writes nothing, and records `fresh_key_check: pass | fail | not run` on its runs row; a fail (exit 5) is a credential event and goes to the operator at once (why: queue/prompt-batch-2026-W40 candidates_added_2026_09_25_key_check) (rev. 2026-09-27). The runs row names every seal-check id the gate printed in the sitting, not only the one it meant to file (why: `notes/2026-10-19-audit-one-continuity-check-with-no-ledger-row`) (rev. 2026-10-19).

(h) A command driven by osascript can report failure after it partly ran: read its log or the target's state before invoking again, never re-run on the error text alone (why: `notes/lesson-2026-09-21-an-osascript-that-reports-failure-may-still-be-running`). The osascript shell carried no ssh-agent (measured 2026-09-21 and 2026-09-28, bridged Cowork sittings, manual mode), so a commit made there passes `-c commit.gpgsign=false`, and signing (a re-sign, a tag, a signed pin) runs as a hashed script in Terminal launched by osascript, announced to the operator before the window opens, its output read from a log in the dated folder (why: `notes/lesson-2026-09-21-osascript-has-no-ssh-agent-so-a-signed-commit-fails-silently`; `notes/2026-09-28-lesson-terminal-do-script-is-a-new-method`) (rev. 2026-09-29).

(i) A sitting whose context was compacted records each compaction's time on its runs row as `compactions: [<ISO UTC>]`, and cites ledger rows, never recollection, for anything done before the latest one (why: notes/2026-10-05-lesson-long-sittings-leave-no-compaction-marker) (rev. 2026-10-12).

(j) Echo's cross-check of a public claim is optional: a sitting asks Echo only when <OPERATOR-NAME> asks for it in that sitting, and otherwise a claim that rests on a reading goes out on the sitting's own check, which the runs row names. When she is asked, the handoff is file reads only, sized to that: numbered claims, each marked confirmed, contradicted or not found against named sources. Her result is evidence and is spot-checked; the runs row records the job id and the per-claim verdicts, or 'could not run', and a report says when a finding rests on her check alone. Echo holds no account on either board. Echo is not called while the operator's work account is logged in on the Mac, which `echo-call` enforces by refusing with exit 4 (why: queue/prompt-batch-2026-W42 line 9; made optional by the operator 2026-10-26, W44 line 9, because the checks added little and each call slowed the Mac until the model unloaded, notes/2026-10-26-lesson-echo-handoff-cannot-exec-and-timed-out-under-swap) (rev. 2026-10-26).

(k) A sitting's own board write — a comment, a vote, or a post with <OPERATOR-NAME> in the sitting — goes through `sh ~/Projects/1f916-agent-toolkit/sitting/board-write.sh /tmp/1f916-<YYYY-MM-DD> <route> <body.json>` in Ghostty, the body a file hashed on both sides. A post is written only when the body's sha-256 is passed as a fourth argument after <OPERATOR-NAME> approved that exact text, recorded on the runs row; without it the launcher ends `NEEDS APPROVAL <sha>` and writes nothing. The launcher asserts the deployment clone is on main and clean, and one 1Password prompt covers the gate's write and the seal-check brief rule 7 asks for. Write the `board` row from the gate's masked result and the seal-check id on the runs row; a refused write is reported, never re-sent reshaped. The Colony's launcher is `docs/colony.md`'s. Both read their 1Password references, never secrets, from `~/.config/1f916/sitting.env` on the Mac (`GATE_ITEM_REF`, `COLONY_KEY_REF`), so no vault reference lives in this repository (why: `queue/task-2026-10-26-sitting-posting-instructions`) (rev. 2026-10-26).
